# モバイル Skill: 利上げ時の端末分割払い・設備投資影響

## 前提
- 本文書は nexus6-se-workshop の Demo 用ナレッジであり、数値・事例はすべて想定値である。
- 個人情報、実在企業の機密、実顧客の行動履歴は含めない。
- 対象事業部は モバイル通信 である。
- 対応シナリオは シナリオ3: 日銀の金融政策転換（利上げ・金利上昇）。
- Agent 2 は影響有無の評価、Agent 3 は事業部別 Next Action の草案作成に使う。

## 適用シナリオ
- 外部ニュースのトリガー: 政策金利上昇により端末分割払い、リース、基地局投資の資金コストが上昇する局面。
- ニュースは判断の入口であり、最終判断は業務システム内のデータで行う。
- 速報段階では 直近月、前月、前年同月 の 3 つを比較する。
- 月次確定後は予算、施策、リスクイベントを含めて再評価する。
- 複数事業部に波及する場合は共通顧客 ID ではなく各事業の業務 ID を起点に見る。

## 参照データ
- 主なテーブルまたはモデル: `installment_details, contracts, usage_billing, network_station, plan_rules`。
- 日次スナップショットは最新日だけでなく、ニュース前 7 日平均と比較する。
- 金額は原則 JPY 換算後に比較する。外貨建てのまま判断しない。
- 法人、個人、高ランク、低スコアなどのセグメント差を必ず残す。
- NULL は欠損とは限らないため、DS.md のデータ品質メモを優先する。

## 判断ロジック
1. ニュース種別を `シナリオ3: 日銀の金融政策転換（利上げ・金利上昇）` に分類し、対象期間をニュース日から前後 30 日に設定する。
2. `installment_details` を起点に対象母集団を抽出する。
3. 直近月と前月の差分、前年同月差、7 日移動平均の乖離を計算する。
4. 分割払い残高、実質年率、残回数、基地局設備投資予定を確認し、月額負担と解約リスクを判断する。
5. キー指標 `変動金利分割比率, 月額負担増, 残債月数, 解約率, 設備投資回収月数` を同じ粒度で並べ、単一 KPI だけで判断しない。
6. 影響が売上、粗利、離反、信用リスクのどれに出ているかを分類する。
7. 施策候補は「即時」「翌月」「監視継続」に分ける。

## 業務しきい値
| レベル | 目安 | 判断 |
|---|---:|---|
| 影響なし | 通常監視 | 基準未満。月次レポートに記録する。 |
| 要注意 | 担当確認 | しきい値を超過。前月比と同一季節を確認する。 |
| 要対応 | 施策検討 | 粗利・離反・リスクのいずれかが大きく、翌営業日までに案を出す。 |
| 緊急 | 責任者判断 | 顧客影響または損失拡大が想定され、即日エスカレーションする。 |
| KPI 変化率 | 要注意 5% 以上 | 要対応 10% 以上。季節性がある場合は前年同月差を優先。 |
| 粗利または損失影響 | 要注意 1,000 万円相当 | 要対応 3,000 万円相当。Demo 用の概算値。 |
| 顧客影響 | 要注意 0.5pp 変化 | 要対応 1.0pp 変化。母数 1,000 未満は参考値。 |

## キー指標
- KPI1: 変動金利分割比率。ニュース前後で同じ集計粒度にそろえる。
- KPI2: 月額負担増。ニュース前後で同じ集計粒度にそろえる。
- KPI3: 残債月数。ニュース前後で同じ集計粒度にそろえる。
- KPI4: 解約率。ニュース前後で同じ集計粒度にそろえる。
- KPI5: 設備投資回収月数。ニュース前後で同じ集計粒度にそろえる。
- 補助指標: 問い合わせ、キャンセル、アラート、施策反応の急変。
- 財務指標: 売上、粗利、費用、リスク損失を JPY で見る。
- 顧客指標: 母数、対象率、変化幅を同時に提示する。

## 過去の想定事例
- 事例 ID: `2025-Demo-BOJ-03`。
- 利上げ 0.5%pt の想定で変動型分割の月額負担が平均 180 円増え、低 ARPU セグメントの問い合わせが 12% 増加したため、既存契約は据え置き、新規契約のみ料率を改定した。
- この事例は Demo 用の架空ケースであり、実在企業の実績ではない。
- 同じニュース見出しでも、KPI がしきい値未満なら「監視継続」とする。

## 3 シナリオを意識した実例
- 日銀政策転換ニュース `article-boj1.html` では、端末分割の変動金利比率と設備投資の調達条件を分けて評価し、顧客影響と財務影響を混同しない。
- Agent 2 の出力には、該当シナリオ、根拠 KPI、しきい値判定、未確認データを含める。
- Agent 3 の出力には、事業部向けの推奨アクション、期待効果、確認担当を含める。

## 判断の例外
- データ欠損が 20% を超える期間は、影響判定ではなくデータ確認タスクとして扱う。
- 単発キャンペーン、システム障害、棚卸などの既知イベントがある日は除外候補にする。
- 実在企業名がニュースに含まれても、本文書では「競合 A」「海外ベンダー B」などに一般化する。
- 顧客単位の特定や個人属性の推測は行わない。

## 推奨アクション
- 速報: 影響あり/なし、最大影響 KPI、確認すべきテーブルを 3 行で返す。
- 深掘り: セグメント別に上位 3 要因を出し、過去事例と照合する。
- 施策: 価格、ポイント、与信、通知などの候補を過剰適用しない。
- 記録: 判断に使った期間、しきい値、除外条件を分析ログへ残す。
